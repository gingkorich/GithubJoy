geerlingguy/chronytopGolite

该仓库实现一个面向 chrony 的终端监控工具，它通过本地 chronyc 和 proc 文件系统获取时间源、跟踪、带宽、进程资源与受限客户端信息，并使用 Go 标准库绘制可显示或隐藏的面板，同时将面板可见状态和采样间隔写入用户配置目录以便下次恢复。

实现逻辑

Q1 · 运行入口和主要数据流是如何分层的？

基于 README 与目录结构推断，main.go 作为静态二进制入口，负责解析 -i、-p 等参数并启动终端界面；chrony.go 与 stats.go 分别对应 README 描述的 chronyc 采集和 /proc 指标处理。panels.go、draw.go、screen.go 和 format.go 再完成面板布局、绘制与数值格式化。

来源：README.md main.go chrony.go stats.go panels.go draw.go screen.go format.go

Q2 · 核心数据来源与权限模型是什么？

核心数据来自 chronyd 的客户端查询和本机系统指标；README 明确普通用户可看 tracking、sources、net、system，而 server/offenders 需要 root、opencommands 或能写 /run/chrony 的组权限。实现上不打开网络连接，只通过 /usr/bin/chronyc 和 /proc 获取输入。

来源：README.md chrony.go main.go

Q3 · 面板与采样配置如何持久化，以及启动时如何覆盖？

config.go 承担设置持久化；README 说明退出时把可见面板和采样间隔保存到 ~/.config/chronytop/chronytop.conf，启动时恢复，但命令行 -i 会覆盖已保存间隔。README 还给出属主检查与临时文件写入，避免在 sudo 下误写到非 root HOME 或跟随 symlink。

来源：README.md config.go

Q4 · offenders 列表刷新策略和参数过滤如何降低开销？

offenders 面板使用 chronyd 的 clients/serverstats 数据，README 指出列表后台每 10 秒刷新；-p 由 chronyd 本身过滤低包数客户端，所以公共服务器上不必每次主循环拉取完整列表。这样把昂贵的大列表刷新与常规面板采样周期解耦。

来源：README.md chrony.go panels.go

Q5 · 终端绘制和交互状态如何组织？

终端交互围绕面板显示和采样速度组织；README 列出 1-7 切换面板、+/- 调速、Esc/q 退出，screen.go、draw.go、panels.go 与 term_linux.go 按目录结构推断分别处理屏幕刷新、绘制、面板内容和 Linux 终端能力。format.go 用于把数值输出成适合终端显示的文本。

来源：README.md screen.go draw.go panels.go term_linux.go format.go

Q6 · 错误处理和安全边界体现在哪些实现选择上？

安全边界体现在输入与输出两端：README 规定以绝对路径调用 chronyc、最小环境且无 shell，并把非打印字符从显示内容中剥离，避免终端转义注入。配置写入只在设置改变且目录属主匹配时发生；CI 还运行 go vet、staticcheck、gosec 和 govulncheck。

来源：README.md config.go .github/workflows/ci.yml

技术栈
Go / CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o chronytop .
适用场景
  • 在 Linux 终端实时监控 chrony 的每秒请求数、sources、tracking、带宽、CPU 和内存。
  • 定位被 chronyd 限流最多的客户端或高流量来源。
  • 以 btop 风格快速检查本机或服务器上的 NTP 时间服务健康状态。
风险
  • 依赖 Linux、chrony 4.0 或更高版本以及 /usr/bin/chronyc，环境路径或版本不满足时功能会受限。
  • server/offenders 面板需要 root 或较复杂的 chrony 权限配置，旧版组权限还可能给同组用户暴露完整控制 socket。
  • offenders 列表每 10 秒才后台刷新，不适合观察毫秒级突发或实时逐秒变化。
  • 配置保存依赖用户目录和文件属主检查，在 sudo 下 HOME 与运行用户不一致时会跳过保存。
  • 项目只读取 chronyc 与 /proc，若 chronyd 权限放宽或运行环境被篡改，本地控制面暴露风险需要额外控制。
