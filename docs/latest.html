nvm-sh/nvmShelllite

nvm 是一个基于 POSIX shell 函数的 Node 版本管理项目，通过 install.sh 初始化用户目录，并由 nvm.sh 注册 install、use、alias、ls 等命令。它用版本目录、别名文件、默认别名和 current 软链保存状态，通过修改 PATH 切换运行环境，支持 .nvmrc、镜像、global packages 迁移以及 Docker/CI 场景。整体设计强调按 shell 加载而非全局二进制，并覆盖多平台兼容性与测试目录。

实现逻辑

Q1 · nvm 的入口和命令发现机制是怎么实现的？

README 的安装片段表明用户 shell 需要 source nvm.sh，nvm 不是通过 which 找到的二进制，而是当前 shell 中的函数。install.sh 负责把仓库放到 NVM_DIR 并写入 profile，bash_completion 则可选提供补全。

来源：README.md install.sh nvm.sh bash_completion

Q2 · 版本、别名和 LTS 这些核心概念在实现中如何组织？

目录树中的 Aliases 测试路径把 nvm_resolve_alias、nvm_resolve_local_alias、LTS alias 等处理拆成独立场景，说明别名先解析到目标版本，再由 ls/install/use 使用。默认别名、循环 alias、含空格或特殊字符别名都在测试边界内处理。

来源：test/fast/Aliases/nvm_resolve_alias test/fast/Aliases/nvm_resolve_local_alias README.md

Q3 · nvm 安装 Node 版本时依赖哪些外部资源？

README 说明 installer 可用 git、curl 或 wget，并支持使用 node binaries mirror。测试 mock 中存在 nodejs.org-dist-index.tab 与 iojs.org-dist-index.tab 等文件，表明版本索引和下载源是安装逻辑的关键输入。

来源：README.md install.sh test/fast/Unit tests/mocks/nodejs.org-dist-index.tab test/fast/Unit tests/mocks/iojs.org-dist-index.tab

Q4 · 状态与持久化主要写在哪里，nvm use 又怎样改变 shell？

版本安装和选择的状态落在用户 NVM_DIR 下的版本目录、别名目录和 current symlink。测试路径显示 nvm use 会创建或改变 current symlink，并可按 NVM_SYMLINK_CURRENT 关闭；deactivate/unload 负责清理 shell 中的 nvm 变量和路径。

来源：test/fast/Running 'nvm use x' should create and change the 'current' symlink test/fast/Running 'nvm use x' should not create the 'current' symlink if $NVM_SYMLINK_CURRENT is false test/fast/Running 'nvm deactivate' should unset the nvm environment variables test/fast/Running 'nvm unload' should unset all function and variables

Q5 · 错误处理和调用方状态隔离有哪些边界？

Sourcing 测试要求加载 nvm.sh 不修改调用方参数或 IFS，失败检查路径会传播 exit code。install/use 相关测试还覆盖无效版本、循环 alias、错误权限和 stale hashed node，说明实现关注可预测失败而不是污染当前 shell。

来源：test/fast/Sourcing nvm.sh should not modify parameters of caller test/fast/Running 'nvm' should not change or export the caller's IFS test/fast/Unit tests/failed checks propagate their exit codes test/fast/Running 'nvm install' with an invalid version fails nicely test/fast/Running 'nvm use' does not leave a stale hashed node

技术栈
Shell / Makefile
适用场景
  • 在多个 Node.js 主版本之间切换进行开发、测试或发布
  • 通过 .nvmrc 固定项目所需 Node 版本
  • 在 Docker/CI 环境中安装指定 Node 版本并运行构建
  • 从旧版本迁移 npm global packages 或按文件默认安装全局包
  • 使用自定义镜像下载 Node binaries
风险
  • nvm 是 shell 函数，新终端、非交互 Docker 或 profile 未加载时会出现 nvm: command not found。
  • 安装脚本会尝试修改 bash/zsh/profile，可能需要手动设置 PROFILE 或避免插件重复注入。
  • PATH、npm global packages、系统 Node 与 nvm Node 混用时可能产生权限和版本不一致。
  • Fish、FreeBSD、Windows 原生支持受限或依赖替代方案。
  • 别名解析和版本文件存在边界情况，包括循环 alias、特殊字符、CR/NUL、隐藏目录和权限错误。
